Этот проект — идеальный пример того, как за внешней легкостью и фановым интерфейсом скрывается мощная научная математика, продуманная синхронизация данных и крутые практики фронтенд-гигиены. 

Давай разберем по косточкам, как тут всё устроено, чтобы тебе было максимально легко дописывать новые фичи и ловить кайф от кодинга!

## 🧠 1. Мозг приложения: Алгоритм прогрессии (`src/lib/protocol.js`)

Самая большая ценность PawTimer — это адаптивный алгоритм тренировок. Мы не просто даем случайный таймер; приложение само решает, сколько собаке комфортно просидеть одной.

### Как работает умный расчёт времени?

1. **Базовая планка (Safe Alone Time)**:
   Приложение рассчитывает безопасное время на основе истории тренировок. Но оно делает это не простым средним арифметическим! Используется взвешенная формула: **чем свежее тренировка, тем больше её вес**. Старые тренировки (старше 7 дней) почти не влияют на результат, чтобы отражать реальное состояние собаки прямо сейчас.
   
2. **Штраф за прогулы (Gap Penalty)**:
   Если тренировок не было несколько дней, алгоритм понимает, что собака могла подзабыть навык. Он автоматически срезает целевое время на следующую тренировку (до 38% при длительном простое), чтобы не вгонять питомца в стресс.

3. **Адаптивный режим восстановления (Recovery Mode)**:
   Если во время сессии собака испытала стресс, приложение прерывает обычный рост времени и включает **Confidence Rebuild (Восстановление уверенности)**:
   * **Слабый стресс (Subtle Distress)**: Время временно падает. Любая спокойная тренировка засчитывается в прогресс восстановления.
   * **Сильный стресс (Active/Severe Distress)**: Запускается жесткий многошаговый план реабилитации (например, цепочка `60с → 120с → 120с`). Пока собака не пройдет её идеально спокойно, время расти не начнет.

4. **Оценка рисков отката (Relapse Risk)**:
   Анализирует частоту паники, нестабильность последних тренировок и пропуски. На основе этого выставляется статус готовности (Readiness) от `Low` до `High`, который красит интерфейс в предупреждающие тона.

## ☁️ 2. Локальность и Синхронизация (`src/features/app/storage.js`)

Мы любим Local-First архитектуру. Приложение отлично работает без интернета на встроенном `localStorage`. Но если подключить Supabase (через переменные окружения `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`), включается магия бесшовной синхронизации!

### Почему этот слой сделан невероятно круто?

* **Минимум зависимостей**: Синхронизация написана на чистом `fetch` через Supabase REST API без использования тяжелого SDK Supabase.
* **Идентификация изменений (Tombstones)**: При удалении записей о тренировках они не стираются из памяти бесследно (иначе устройство-напарник никогда бы не узнало об удалении). Вместо этого создается специальный маркер удаления — **Tombstone**, который синхронизируется с базой данных и подчищается на клиенте только спустя 30 дней.
* **Разрешение конфликтов (Conflict Resolution)**: Если ты потренировал собаку с телефона, а жена удалила тренировку с планшета, приложение сравнивает ревизии записей, таймстампы изменений и даже контрольные суммы содержимого, чтобы выбрать математически верного «победителя» без потери данных.
* **Частичная синхронизация (Partial Sync)**: Если в твоей Supabase бэкенд-базе нет каких-то таблиц (например, для отслеживания кормлений или прогулок), приложение автоматически определит это через профиль возможностей бэкенда (`syncCapability`), перейдет в режим частичного сохранения и не будет спамить ошибками! Неподдерживаемые данные будут бережно храниться на твоем устройстве локально до лучших времен.

## 🎨 3. Премиальный визуальный стиль (`src/styles/`)

Мы заботимся о визуальной эстетике. В 2026 году мы внедрили премиальную систему дизайн-токенов.

* **Дизайн-токены**: В папке `src/styles/tokens/` лежат атомарные стили для отступов, радиусов закруглений, теней, анимаций и типографики. Больше никаких хардкодных пикселей в коде!
* **Теплый минимализм**: Мы заменили скучные холодно-белые цвета на уютную теплую палитру, которая снижает тревожность у человека во время тренировок его любимого хвостика.

### 🛡️ CSS-Гигиена (`scripts/check-inline-style-hygiene.mjs`)
У нас действует строгое правило: **никаких инлайн-стилей (`style={{ ... }}`) в JSX!** 
Инлайн-стили ломают чистоту кода и кэширование CSS. Чтобы разработчики случайно не притащили инлайн-стили в код, у нас написан кастомный скрипт-анализатор. Он сканирует файлы в папке `src` и блокирует сборку при обнаружении инлайн-стилей. 

> 💡 **Исключение**: Если инлайн-стиль жизненно необходим (например, для динамического расчёта процентов заполнения прогресс-бара), добавь к этой строке комментарий `// INLINE_STYLE_TECHNICAL_EXCEPTION`, и линтер пропустит её.

## 🚀 Как запустить и разрабатывать локально

### Требования к окружению
> [!IMPORTANT]  
> Для запуска тестов и линтеров требуется **Node.js версии 18 или новее** (лучше всего Node 20 или 22 LTS). Устаревшие версии Node (например, Node 12) выбросят синтаксическую ошибку при запуске тестового окружения из-за использования современного синтаксиса (Optional Chaining `?.` и т.д.).

Для удобного переключения версий Node.js рекомендуем использовать менеджер версий **nvm**:
```bash
nvm install 20
nvm use 20
```

### Команды в терминале

1. **Установка зависимостей**:
   ```bash
   npm install
   ```

2. **Запуск локального сервера разработки (Vite)**:
   ```bash
   npm run dev
   ```
   Приложение откроется на `http://localhost:5173`.

3. **Запуск тестов (Vitest)**:
   ```bash
   npm test
   ```
   Этот проект покрыт огромным количеством тестов, проверяющих алгоритм прогрессии и синхронизацию. Запускай их перед каждым коммитом!

4. **Проверка инлайн-стилей**:
   ```bash
   npm run check:inline-styles
   ```
   Убедись, что твоя верстка соответствует правилам CSS-гигиены проекта.
